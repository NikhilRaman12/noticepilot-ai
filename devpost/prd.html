Behavior and measurable acceptance criteria

Input and analysis

  • Blank or whitespace-only input disables Analyze notice and displays “Paste a notice or try our sample to get started.” The sample action remains available.
  • Loading the sample fills the notice input; the same Analyze action starts the sample workflow.
  • While analysis runs, a restrained loading state is visible and a second submission cannot start. When processing ends, the action is restored.
  • For invalid or insufficient input, the original text stays present, the problem is explained in plain language, and edit/sample/retry paths remain available.

Results and evidence

  • Successful analysis places the explanation and results on the same screen and keeps the original notice available.
  • Each important result exposes “View evidence” with the exact source excerpt and a page or section reference where available.
  • Every result uses an explicit supported, needs-verification, or not-found status; color is not the sole status indicator.
  • Each checklist item links to evidence or is labelled as a suggestion. An unmentioned document is never shown as mandatory.
  • Dates retain source wording; a date is not presented as a submission deadline without contextual evidence. No deadline is inferred from today's date.
  • Ambiguous and missing details appear in Needs your attention, not as settled facts. A conflict, if included, shows both source passages with a warning.
  • A first-time user can complete the bundled-sample journey and inspect evidence in under one minute during the demo.

Failure recovery

  • On analysis failure, the full input remains and the user sees “We couldn't analyze this notice. Your text is still here—please try again.” with Retry and Edit actions.
  • A failed attempt does not replace prior results with unsupported output; any prior results are identified as belonging to the previous successful analysis.
  • After editing and retrying, the user does not need to restart the workflow or re-enter the notice.
Important states and boundaries
  • Empty: Helpful inline prompt; no alarming error or analysis request.
  • Ready: Sample or pasted text is present and can be analyzed.
  • Analyzing: Restrained progress, duplicate submission prevented.
  • Insufficient input: Preserve text, explain what source information is needed, offer edit or sample.
  • Failure: Preserve text, show retry and edit; never create success-shaped unsupported results.
  • Partial analysis: Show only source-supported results; mark unresolved information explicitly.
  • No account, persistent storage, API key, or authoritative advice is required for this proof of concept.
Look, decisions, and what is deferred

Evidence-first clarity: deep navy, muted teal, warm off-white, readable type, generous spacing, responsive layout, calm civic-tech tone. No chatbot look, robot imagery, glowing gradients, excessive glass, or decorative AI effects.

  • Now: One fictional text-first notice workflow, source-linked actions, dates and documents, uncertainty states, and resilient retry behavior.
  • Deferred: PDF upload and highlighting, broad real-world notice coverage, integrations, accounts, persistence, and external API dependence.
  • Stretch only: A deliberately conflicting-date sample, if it fits after the core experience works reliably.
  • Open for spec: The exact insufficient-text validation boundary and source-location representation for pasted text. Neither may weaken the user-facing evidence and recovery behavior.
