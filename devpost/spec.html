Data contract and evidence invariant

A finding contains an ID, kind, short explanation, verification status, evidence spans, and optional explicit/suggestion classification. An evidence span stores inclusive start and exclusive end offsets into the exact analyzed input, the exact quote, and a 1-based line or actual heading when available.

Invariant: quote === sourceText.slice(start, end). Not-found findings have no evidence span. Conflicting findings retain both relevant spans. The current editable text and last successful result are separate, so failed retries never misattribute results.

All data lives in browser memory. Refreshing or closing the tab clears the notice and results; no account, database, or saved history.

Testing and run commands
  • npm install then npm run dev; open the local URL printed by Vite.
  • npm test covers rule extraction, exact source slices, supported/ambiguous/conflicting/not-found cases, and UI recovery.
  • npm run build checks the TypeScript/Vite production build.
  • Record locally: sample → analyze → inspect exact evidence → show unresolved information. The short video and public GitHub repository are required; deployment is optional.
  • Include the learner-selected open-source license in LICENSE and local install/run/test plus demo-video guidance in README.md.

Official references: Vite, React, TypeScript, Vitest, React Testing Library.

Trade-offs and unresolved checks
  • Rule-based extraction is reproducible and auditable but deliberately incomplete; unfamiliar phrasing produces partial results, never invented certainty.
  • Plain text supports exact excerpts and line/real-heading anchors, not page numbers or PDF highlighting.
  • No application runtime is installed yet; verify Node/npm compatibility and pin package versions early in the build.
  • Conflict representation and tests are specified; include a conflicting-date sample only after the core demo is reliable.
